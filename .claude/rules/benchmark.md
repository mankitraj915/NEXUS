# Benchmark methodology

- `backend/docs/benchmark-evaluation-*.{md,json}` are generated by
  `scripts.benchmark evaluate`; never hand-edit them. The JSON sidecar records the commit
  (`-dirty` if uncommitted), CPU, library versions and model revisions.
- Split roles are fixed: BEIR "test" (300) = official SciFact dev, used for tuning; BEIR
  "train" (809) = untuned check. Official SciFact test labels are not public; never infer them.
- Choose parameters on the tuning split only, and report any new configuration on both splits.
- Quality metrics reproduce exactly for the same index and model revisions; latency does not.
  Compare latency only between retriever families, not neighbouring configurations.
- `scripts.benchmark verify` is the cheap check; rerun the full evaluation only when
  retrieval code, models or the harness changed.
- ADRs record past decisions: add a dated addendum instead of rewriting the original text.
